# WCNS 可发布版本开发与算例验收计划

状态：自 2026-09-02 起生效；与 [`development-roadmap.md`](development-roadmap.md) 配套使用。

本文把阶段 M--O 的实现边界、自动卡口和最终算例验收固定为可执行规格。阶段 K、L
已有候选版本的人工检查并入阶段 O，不再作为继续开发的前置条件；这不追认尚未完成的人工
验收，也不降低任何自动测试要求。数学和离散算法仍以仓库根目录的
[`算法补充.md`](../算法补充.md) 为准。

## 1. 流程与发布目标

1. 从当前阶段 L 候选提交建立连续的发布开发线，依次完成阶段 M、N、O；阶段之间通过自动
   卡口后直接继续，不等待逐阶段人工批准，也不在中间阶段合并 `main`。
2. 每个小任务仍须“实现、局部测试、受影响回归、Git 提交、远程同步”；失败的正式自动验收
   仍须记录，普通编译调试失败不单独提交。
3. 阶段 M、N 形成不可移动的里程碑标签。只有阶段 O 的生产算例矩阵全部达到预先冻结的
   容差后，才形成发布候选并提交项目负责人进行一次集中人工验收。
4. 最终发布程序必须能够仅通过配置文件和 CGNS 网格完成初始化、推进、停止、监测、流场
   输出及重启，算例不得通过修改或重新编译生产 C++ 代码来定义。
5. 发布候选验收必须调用正式可执行程序和正式 I/O 路径；测试夹具、直接调用内部残差函数或
   手工构造绕过配置的结果只能作为单元测试，不能替代系统验收。

首个可发布版本的边界固定为：静止结构网格、量热完全气体、层流 Euler/Navier--Stokes、
显式 SSPRK3、CGNS 输入/流场/检查点和 Tecplot/TXT 输出。湍流模型、动网格、隐式推进、
AMR、多重网格、GPU 和真正的并行 CGNS 写入不作为首发前置；文档必须将这些列为未支持，
不能提供可开启但数学或通信路径不完整的占位配置。

## 2. 当前状态检查与缺口

| 方面 | 当前能力 | 发布前缺口 |
|---|---|---|
| CGNS 与多块 | 一个 CGNS zone 映射一个 `StructuredBlock`，可读取连接和物理边界 | 尚不能把一个大 zone 切成多个计算块，也不能按子区间读取坐标 |
| MPI 分配 | `BlockDistribution::balanced` 按单元数对完整块做确定性 LPT 分配 | zone/block 数少于 rank 数时会出现空闲 rank；粗块负载也可能严重失衡 |
| 数值推进 | 已有两套几何 profile、无粘/粘性残差、源项和 SSPRK3 | 缺少生产配置、初场、统一驱动、停止原因和重启闭环 |
| 监测 | 内部测试可计算残差和算法回退计数 | 缺少持久化残差、探针、统计量、守恒账目和自定义量注册接口 |
| 输出 | 网格读取路径已存在 | 缺少 CGNS/Tecplot 流场输出、时间序列、输出调度、原 zone 重组和检查点 |
| 算例 | 单元及专项算法测试较完整 | 缺少通过生产入口运行的多物理、多拓扑、多 rank 系统算例矩阵 |

因此，当前完整 block 的贪心分配可以保留为“叶块到 rank 的第二级分配器”，但不能继续兼任
结构网格分区器。发布路径必须先产生确定的叶块分区，再执行现有负载分配。

## 3. 结构网格二次剖分与并行分配

### 3.1 借鉴 PHengLEI 的范围

PHengLEI 的 `GridPartition::PartitionStructGrid` 通过 `Pre_StrGridPartition` 对结构块进行二分：
反复从未分配块中选择较大块，向当前低负载进程分配；必要时沿可行的较长方向切开，并为
两个子块建立内部连接。WCNS 借鉴“先切块、后分配、保存原 zone 映射”的思路，不照搬其
固定阈值或原始内存管理实现。参考代码位置为：

- `PHengLEI/Main/src/GridPartition.cpp`；
- `PHengLEI/API/PreProcess/src/Pre_StructGridPartition.cpp`；
- `PHengLEI/API/PreProcess/src/Pre_Block_Struct.cpp`。

### 3.2 数据模型和两级流程

新增独立的 `StructuredPartitionPlan`。每个叶块至少保存：

- 原 CGNS base/zone 标识与稳定的全局叶块 `BlockId`；
- 原 zone 单元半开区间 `[cell_begin, cell_end)` 和由其导出的顶点闭区间；
- 三方向单元数、单元总数、父叶块和切分代次；
- 物理边界子片、块间连接子片、周期变换和最终 owner rank；
- 用于输出重组及跨不同 rank 数重启的原 zone 映射。

生产顺序固定为：

```text
读取所有 zone 的尺寸和拓扑元数据
-> 生成或细化 StructuredPartitionPlan
-> 检查覆盖、连接和最小模板尺寸
-> 将叶块按单元负载分配到 rank
-> 广播计划摘要并逐 rank 校验哈希
-> 仅按 owner 读取本 rank 叶块的 CGNS 坐标子区间
-> 建立局部块、连接和 halo
```

`BlockDistribution` 继续负责最后一步叶块 LPT 分配；不得在其中隐式改变网格拓扑。

### 3.3 触发、切分和确定性

配置提供：

- `partition.mode = zones_only | auto_split | force_split`，发布默认值为 `auto_split`；
- `partition.allow_idle_ranks = false`，发布默认不允许可行情况下静默空闲；
- `partition.max_load_ratio`，用于触发已有多 zone 网格的进一步负载细化；
- `partition.min_cells_per_active_direction`，用户值不得低于当前 profile 的数学下限。

`auto_split` 在原 zone 数小于 rank 数，或预计最大/平均负载超过阈值时细化。算法采用确定性的
受约束递归二分：优先处理最大叶块，并尝试让新块接近目标 rank 负载；候选方向依次比较
模板合法性、负载误差、新增界面面积和方向长度。相同评分依次以原 zone 编号、父区间、
`i/j/k` 方向和较小切点破除平局。所有 rank 必须从相同元数据得到相同计划摘要。

一个切口使用共享的一层顶点平面，两个子块的真实单元区间不重叠。切分后：

1. 原物理边界与子块面取交，只把非空子片复制给子块；
2. 兄弟块在切面上生成成对、互逆、单位轴变换的内部连接；
3. 原有一对一连接先与 receiver 子块面取交，经有符号轴变换映射到 donor 原 zone，再与
   donor 叶块取交，生成互逆连接子片；
4. 平移或旋转周期的 $Q,\boldsymbol d$ 原样继承，接收/供体索引变换继续满足现有连接约定；
5. 边界名称和原 CGNS 标识保留，以便配置匹配、监测和输出重组。

当前 `phenglei_wcns` 活跃方向严格下限为 4 个真实单元，`scmm6_wcns` 为 5 个真实单元；
发布默认的实用下限取 `max(8, 2*ghost_width+1)`，且不能小于所选 profile 的严格下限。
二维退化方向不参与切分和下限判断。若在这些约束下无法产生不少于 rank 数的叶块，且
`allow_idle_ranks=false`，程序须在读取完整坐标和分配大数组前报告最大可用 rank 数并失败；
不得静默留下空闲进程或生成模板不足的碎块。

### 3.4 CGNS 子区间读取和验证

CGNS reader 增加顶点 hyperslab 读取，owner rank 只读取叶块所需的坐标子区间；不能让每个
rank 先复制全部原 zone 再丢弃。拓扑元数据可以由根 rank 读取后广播，或由所有 rank 只读
读取，但最终摘要必须相同。

分区计划投入求解前逐项验证：

- 每个原 zone 的每个真实单元恰好被一个叶块覆盖，无遗漏、重复和越界；
- 所有叶块满足 profile 模板、ghost 宽度和最小尺寸约束；
- 每个内部或周期连接存在唯一互逆伙伴，索引变换、方向、面积和端点一致；
- 物理边界子片并集与原边界完全相等且互不重叠；
- 全局 `BlockId`、消息 tag 输入和 owner 唯一，所有 rank 的计划哈希相同；
- 可行时每个 rank 至少有一个叶块，并记录最大/平均单元负载比及切分数量。

## 4. 运行模式与停止机制

### 4.1 公共状态和停止原因

配置必须显式选择 `run.mode = steady | unsteady`。两种模式都必须提供正的 `max_steps` 作为
硬安全上限；`max_wall_time` 可选，用于批处理作业结束前安全写检查点。每个完整 RK 步完成后，
先更新全局步数、时间和残差，再按固定优先级判断停止并触发一次最终输出。

统一 `StopReason` 至少包括：

- `steady_converged`；
- `physical_time_reached`；
- `maximum_steps`；
- `wall_time_checkpoint`；
- `user_signal_checkpoint`；
- `numerical_failure`。

正常结束、达到安全上限和数值失败必须使用不同退出码。停止原因、最终步、最终时间、残差、
配置摘要和检查点路径写入日志及清单；最终流场调度只能执行一次。

同一步满足多个条件时的优先级固定为：`numerical_failure` 最高；其次是该模式的正常完成
（`steady_converged` 或 `physical_time_reached`）；再次是安全信号/wall time；最后是
`maximum_steps`。因此在第 `max_steps` 步恰好收敛或到达 `t_end` 时仍报告正常完成。

### 4.2 定常计算

定常模式的时间是伪时间，`t_end` 不作为收敛条件。每隔 `check_interval_steps` 对每个已启用
方程分量进行 MPI 全局 $L_2$ 和 $L_\infty$ 归约。参考残差在指定首次检查或参考窗口后冻结：

\[
R_{2,q}=\sqrt{\frac{\sum_{b,c}W_cJ_cR_{q,c}^2}
                            {\sum_{b,c}W_cJ_c}},\qquad
R_{\infty,q}=\max_{b,c}|R_{q,c}|.
\]

求和只覆盖每个叶块的真实单元，$W_cJ_c>0$ 使用当前 profile 已验证的全局守恒权重与
Jacobian；MPI 分别归约分子、分母和最大值。该定义使范数不依赖 zone 切分或 rank 数，
也避免把 ghost 或连接重复单元计入残差。

\[
R_{ref,c}=\max(R_{c,reference},R_{reference\_floor}).
\]

每个分量的通过条件固定为：

\[
\left(R_{2,c}\le R_{2,c}^{abs}
\ \text{或}\ R_{2,c}/R_{ref,c}\le R_{2,c}^{rel}\right)
\quad\text{且（若启用）}\quad
\left(R_{\infty,c}\le R_{\infty,c}^{abs}
\ \text{或}\ R_{\infty,c}/R_{\infty,ref,c}\le R_{\infty,c}^{rel}\right).
\]

只有经过 `min_steps` 后，所有被监测分量连续 `consecutive_checks` 次通过，才返回
`steady_converged`。参考残差和连续通过次数写入检查点，重启不能重新选择更有利的基线。
停滞和残差增长可以报警或按配置判为 `numerical_failure`，但不能被报告为收敛。达到
`max_steps` 时返回 `maximum_steps`，并明确标记“未收敛”。

### 4.3 非定常计算

非定常模式仅以无量纲实际物理时间 `t_end` 为正常完成条件；残差只监测，不参与提前收敛。
每步全局 CFL 时间步须裁剪到不越过 `t_end`，也须裁剪到下一个基于物理时间的精确输出事件，
使最后一步在舍入容差内准确到达目标时刻。首版不以时间插值伪造快照。达到 `max_steps`
但尚未到 `t_end` 时返回 `maximum_steps` 并标记提前终止。

### 4.4 失败和信号处理

非有限状态、正性失败、时间步非正或全局残差非有限必须在 MPI 一致点汇总，所有 rank 以同一
停止原因退出，避免部分 rank 写文件而其他 rank 仍在通信。安全的用户信号或 wall-time 停止只
在完整步边界写检查点。半个 RK 步不作为可重启状态。

## 5. 输出、监测和自定义量

### 5.1 统一调度

流场、统计量、残差和检查点各自使用 `OutputSchedule`，支持：

- `every_steps`；
- `every_time`；
- `explicit_times`；
- `write_initial`；
- `write_final`。

步数与时间事件取并集；同一步或同一时刻只写一次。非定常时间事件通过时间步裁剪精确命中。
所有干净停止原因默认强制最终流场和清单，即使不落在周期点；用户可关闭中间输出，但发布
配置不能关闭数值失败前的诊断记录。文件名包含算例名、step 和 time，采用临时文件完成后
原子改名；默认拒绝覆盖既有输出目录，续算必须显式指定追加或新目录。

### 5.2 流场和检查点

流场支持：

- CGNS：按原 zone 重组，`FlowSolution` 位于 `CellCenter`；至少写
  $\rho,u,v,w,p,T$ 和五个守恒量；
- Tecplot ASCII：每个原 zone 输出一个由单元中心坐标组成的 ordered zone，写配置选择的
  原始量、守恒量和派生量；二维不伪造第三方向变化；
- 配置明确选择无量纲输出或依据参考量还原的有量纲输出，并把约定写入元数据和文件头。

基线单文件实现允许 owner rank 按“原 zone + 原单元区间”打包，由指定 I/O rank 重组。
重组时检查原 zone 每个单元恰好收到一次。大规模并行 I/O 可后续扩展为分片文件，但不能改变
字段和重启语义。

检查点使用无损、可严格校验的 CGNS/项目内部 CGNS 布局，额外保存：步数、实际或伪时间、
时间步、profile、重构/Riemann/输运/边界/源项配置、参考量、派生 $Re/Ma$、残差基线、随机
或用户模型状态、原 zone 映射、配置摘要和格式版本。检查点不是 Tecplot 文件。重启时先按
原 zone 全局位置恢复，再按当前 `StructuredPartitionPlan` 分发，因此必须支持以不同 rank 数
和不同合法叶块划分继续计算。不兼容的维数、网格签名、参考量或算法契约须在推进前失败。

### 5.3 残差历史

残差历史可输出固定列的 TXT 或 Tecplot 时间序列，至少包含：

- step、实际/伪时间、$\Delta t$、CFL、wall time；
- 五个方程分量的全局 $L_2/L_\infty$、冻结参考值和归一化值；
- 总残差、非物理状态计数、重构/黎曼回退计数；
- 当前收敛连续次数及最终 `StopReason`。

只允许指定输出 rank 写文件。不同 rank 数的浮点归约允许预先声明的舍入差，但字段定义、
采样时刻和归一化不能变化。

### 5.4 物理量、统计量和扩展接口

`FieldQuantityRegistry` 提供按名称选择的全场量，首批内建量包括原始量、守恒量、声速、
Mach 数、总焓、熵代理、黏度、涡量、散度、Q 判据、热流和 Jacobian。每个量声明名称、
拓扑位置、依赖、输出单位和计算合法域。派生量只在真实单元或真实面计算，不得读取物理
ghost 的坐标、度量、梯度或其他二级量。

`StatisticRegistry` 首批支持：

- 按物理坐标定位的点探针及最近真实单元信息；
- 命名边界或坐标区域的 min/max/mean/RMS/integral；
- 全局质量、三分量动量、能量和源项/边界通量守恒账目；
- 指定变量极值、壁面力/热流及可定义时的无量纲系数；
- 重构降阶、Riemann 回退、正性修正和非物理状态计数。

统计量随实际/伪时间输出为固定列 TXT 或 Tecplot 文件。关闭某个量时不得创建文件或执行其
专用通信。自定义全场量和统计量分别通过 `IFieldQuantity` 与 `IStatisticQuantity` 注册；
实现者必须声明唯一名称、依赖、位置、归约方式、单位和配置 schema，无需修改输出调度或
求解器主循环。未知名称、循环依赖或重名注册在启动时失败。

### 5.5 清单和可复现性

每次运行输出 manifest，记录程序版本/提交、编译器、MPI 规模、配置摘要、网格签名、分区
摘要、算法选择、参考量、开始/结束时间、停止原因以及所有输出文件。日志区分用户配置错误、
不可行分区、数值失败和 I/O 失败。输出开启与否不得改变推进状态；相关系统测试比较开启和
关闭输出后的内存/重读状态。

## 6. 后续实施阶段

### 6.1 阶段 M：生产入口、配置、分区与初始化

1. M0：冻结阶段设计、配置格式版本、错误策略和测试映射。
2. M1：实现严格 `CaseConfig`、根 rank 读取/广播和各 rank 摘要一致性；拒绝未知、缺失、
   非法单位以及直接输入的 `Re/Ma`。
3. M2：实现本文件第 3 节的 `StructuredPartitionPlan`、CGNS 子区间读取、物理边界/连接切片、
   可行性诊断和叶块到 rank 分配。
4. M3：实现 `FlowInitializer`，支持均匀、区域分片常值、解析/制造初场和兼容 CGNS 初场；
   只写真实单元，再统一派生状态、交换 halo 并施加物理边界。
5. M4：实现正式算例可执行程序的启动链，完成配置、网格、分区、度量、流场和残差工作区
   初始化，但本阶段只进行受控短步 smoke run。
6. M5：建立单 zone 且 rank 数为 1/2/4/8、原多 zone、轴置换/反向及周期连接的分区测试，
   验证覆盖、负载、计划哈希、消息唯一性和串并行初始状态一致。

自动卡口通过后创建阶段 M 里程碑，不等待人工回复，直接进入阶段 N。

### 6.2 阶段 N：运行控制、停止、输出和重启

1. N1：实现唯一 `SimulationDriver` 和 steady/unsteady 状态机，固定生产调用顺序。
2. N2：实现第 4 节的全局残差、`StopController`、停止原因、时间步裁剪和 MPI 一致退出。
3. N3：实现通用 `OutputSchedule`、manifest、目录/命名/覆盖规则和原子写策略。
4. N4：实现残差历史、`FieldQuantityRegistry`、`StatisticRegistry` 及自定义扩展接口。
5. N5：实现 CGNS/Tecplot 流场输出和 TXT/Tecplot 时间序列，包含原 zone 重组与独立重读测试。
6. N6：实现全步检查点、同 rank/异 rank 重启和严格签名校验。
7. N7：建立停止、调度去重、输出开关无扰动、I/O 失败及重启连续性的自动测试。
8. N8：完成配置参考、运行指南、输出字段、扩展接口和故障诊断文档。

自动卡口通过后创建阶段 N 里程碑，不等待人工回复，直接进入阶段 O。

### 6.3 阶段 O：生产算例系统验收与发布

1. O1：提供可版本管理的小型 CGNS 网格，较大网格由确定性生成器产生；所有算例通过同一
   正式可执行程序运行。
2. O2：执行第 7 节的无粘、粘性、源项、时间精度和三维正确性矩阵。
3. O3：执行分区、单块/多块、串行/MPI、连接/周期、输出、停止和重启矩阵。
4. O4：执行错误配置、不可行分区、损坏输入、NaN、无权限/既有输出等失败路径。
5. O5：记录精度、守恒、负载、内存和运行时间基线，补齐发布说明、已知限制和示例。
6. O6：从干净构建完成发布级全矩阵，提交验收报告，创建发布候选标签并同步 GitHub；此时
   才进入项目负责人集中人工验收。批准后合并 `main` 并创建正式版本标签。

## 7. 发布算例矩阵和具体设置

每项首先以小网格进入持续集成，再以表中分辨率执行发布验收。所有数值阈值必须在首次正式
运行前写入算例 manifest；失败后不得只为通过而放宽阈值，若算法证据支持修改，须连同原因
和新基线单独提交。

### 7.1 几何、自由流和分区

1. **单 zone 多 rank 自由流**：二维 $[0,2]\times[0,1]$，$128\times64$ 单元，一个
   CGNS zone，rank = 1/2/4/8；三维增加 $64\times32\times24$ 扭曲网格。两个 profile
   分别运行 10 步，检查每个 rank 非空、覆盖唯一、自由流误差、连接通量和全局守恒。
2. **原生多 zone 等价性**：把同一网格预切为 2、4 个 zone，包含轴置换和轴反向；与运行时
   切分结果比较度量、一步残差和最终状态。
3. **周期连接**：平移周期的二维涡旋，以及绕固定轴旋转周期的三维扇区自由流；检查坐标、
   Cartesian 动量、梯度、面矢量和通量变换。

### 7.2 光滑无粘精度

采用二维等熵涡。区域 $[0,10]^2$、周期边界、$\gamma=1.4$、中心 $(5,5)$、
$\beta=5$、背景速度 $(1,1)$。令 $r^2=(x-5)^2+(y-5)^2$：

\[
\delta u=-\frac{\beta}{2\pi}e^{(1-r^2)/2}(y-5),\qquad
\delta v= \frac{\beta}{2\pi}e^{(1-r^2)/2}(x-5),
\]
\[
T=1-\frac{(\gamma-1)Ma^2\beta^2}{8\pi^2}e^{1-r^2},\qquad
\rho=T^{1/(\gamma-1)},\qquad
p=\frac{\rho^\gamma}{\gamma Ma^2}.
\]

这里的 $Ma$ 只能由算例的 $U_{ref},T_{ref},\widetilde R$ 导出。上式对应本程序以
$\rho_{ref}U_{ref}^2$ 缩放压力的控制方程；若另取 $Ma^2=1/\gamma$，才退化为常见的
$1/\gamma$ 温度扰动系数写法。解析验证器必须使用同一组参考量，不能把该特例隐含写死。

使用 $32^2,64^2,128^2$ 网格推进至 $t=10$，比较解析平移解的 $L_1/L_2/L_\infty$
误差、观测阶、质量/动量/能量守恒、准确终止时间和 1/2/4/8 rank 一致性。两 profile、
四种重构都须覆盖；Riemann 求解器采用代表性交叉矩阵，完整的 4×3 组合用较小网格 smoke。

### 7.3 间断无粘问题

1. **二维薄域 Sod**：$[0,1]\times[0,0.1]$，$400\times40$，$x=0.5$ 左侧
   $(\rho,u,v,p)=(1,0,0,1)$，右侧 $(0.125,0,0,0.1)$，$\gamma=1.4$；上下滑移，
   左右外推/非反射，推进至 $t=0.2$。以一维精确解比较密度/速度/压力 $L_1$、激波和接触
   位置，检查正性和守恒。主组合为 WENO-Z、MDCD-HYBRID 的特征重构配 HLLC/Roe，
   Rusanov 作为耗散基线。
2. **二维四象限 Riemann（Lax--Liu 配置 3）**：$[0,1]^2$，交点 $(0.5,0.5)$；
   NE $(1.5,0,0,1.5)$，NW $(0.5323,1.206,0,0.3)$，SW
   $(0.138,1.206,1.206,0.029)$，SE $(0.5323,0,1.206,0.3)$；外流边界，
   $200^2/400^2$，推进至 $t=0.3$。比较切片、对称关系、积分量、正性和冻结参考图/数据。

### 7.4 粘性、定常停止和源项

1. **Couette 流**：$[0,1]^2$，周期 $x$，下壁 $u=0$、上壁 $u=1$，无滑移并按解析
   设置绝热或等温条件；$32\times64$ 起。用定常模式验证线性速度、壁面剪切、$1/Re$
   缩放、残差连续判据和 `steady_converged`。
2. **静止导热**：周期 $x$，$u=v=0$，$T=1+y$，常压并令 $\rho=p/T$，上下等温壁。
   验证温度、热流、无质量通量和定常停止；HLLC/Roe 需保持静止接触的合理稳定性。
3. **周期粘性制造解**：$24^2,48^2,96^2$，解析速度/温度和完整源项；两个 profile
   比较空间收敛阶、源项体积积分及边界通量账目。
4. **非定常有源制造解**：选取均匀或周期解析状态，使源项具有已知时间解；固定空间误差后
   将 $\Delta t$ 逐次减半，验证 SSPRK3 时间阶、各 RK 子步源项时间和准确 `t_end`。

### 7.5 三维功能

至少包含三维扭曲网格自由流和三维周期制造解/Taylor--Green 类光滑问题，覆盖非零 $w$、
$k$ 向切分、三维度量、涡量和 Q 判据。发布 smoke 分辨率不少于 $32^3$；资源允许时用
$64^3$ 记录参考基线，rank = 1/2/4/8。

### 7.6 输出、重启和停止专项

1. 连续运行 100 步，与 40 步检查点后再运行 60 步比较；重启前后分别使用相同和不同 rank
   数/叶块划分，比较最终状态、残差序列和守恒账目。
2. 同时设置 `every_steps=10`、`every_time=0.05` 和重合的显式时刻，验证事件去重、时间步
   裁剪、初场/最终场和文件命名。
3. 独立重读 CGNS/Tecplot 流场、TXT/Tecplot 历史，逐字段比较内存值；自定义派生量输出与
   离线重算一致。
4. 均匀定常流在 `min_steps + consecutive_checks` 后收敛；Couette 由残差收敛；等熵涡准确
   到 `t_end`；故意过小 `max_steps` 返回未完成；注入 wall-time/安全信号后只在完整步写检查点。
5. 比较关闭和开启各类输出/监测的最终内存状态，除 wall time 外不得改变求解结果。

### 7.7 错误路径和性能烟雾测试

错误矩阵至少包含未知配置项、直接输入 `Re/Ma`、不存在的量、循环派生依赖、不可行切分、
连接不互逆、损坏 CGNS、重启签名不匹配、NaN 状态和输出目录冲突。所有 rank 必须一致失败，
不得死锁或留下貌似有效的最终文件。

性能项记录每 rank 单元数、最大/平均负载比、halo 字节、峰值内存、计算与 I/O 时间。可行
分区的发布目标负载比先定为不大于 1.20；速度提升只记录不设脆弱的 CI 硬阈值，但不得出现
空闲 rank、重复全 zone 坐标内存或明显串行 I/O 之外的非预期全局复制。

## 8. 验收层级和最终卡口

1. **提交级**：小网格单元/集成测试、公式核验、串行回归和可用时的 2-rank smoke。
2. **阶段级**：干净 Release 串行/MPI 构建，阶段专项、1/2/4 rank 等价性和文档/配置重读；
   M、N 通过后自动继续。
3. **发布级**：第 7 节完整矩阵、较高分辨率、1/2/4/8 rank、输出/重启/故障路径和性能记录。

发布级报告必须区分解析误差容差、预期收敛阶、守恒容差、串并行舍入容差和定性参考比较，
并记录每项的配置摘要、网格生成版本和命令。黄金数据须带来源和生成提交，不以未说明的
本机结果覆盖。

只有以下条件同时满足，才提交最终人工验收：

- 阶段 M--O 所有必做项和公共自动卡口通过；
- 单 zone 少于 rank 数时的结构切分、异 rank 重启、停止原因和所有输出格式均有生产路径证据；
- 算例矩阵达到冻结阈值，所有失败和剩余限制在发布报告中明确；
- 工作树干净，远程分支、里程碑/发布候选标签和 GitHub 提交完整；
- README、配置参考、运行指南、算例说明、自定义量扩展说明和版本说明可独立复现结果。

## 9. 额外发现并纳入的模块

除用户明确提出的分区、停止和输出外，发布闭环还必须包含：

- **配置版本和迁移**：配置 schema、检查点格式与输出字段都有版本，未知新版本拒绝读取；
- **边界名称映射**：按 CGNS family/BC 名称绑定条件，切分后名称保持且覆盖完整；
- **守恒审计**：每步可选记录域内守恒量变化、物理边界通量和体源项，定位块连接错误；
- **确定性与 MPI 错误传播**：计划/配置摘要一致，错误在一致通信点全局传播；
- **重启可移植性**：不把 rank 本地顺序作为文件身份，支持不同 rank 数和合法重新分区；
- **资源和 I/O 上限**：在分配前估计内存，明确根 rank 重组的发布规模限制；
- **CLI 与退出码**：统一 `--config`、覆盖/重启选项、dry-run 分区检查和可脚本判断的退出码；
- **可复现元数据**：提交、编译选项、MPI/CGNS 版本、配置和网格签名进入 manifest；
- **二维/三维分别验收**：避免二维路径通过而三维 `k` 向数据、分区或输出未被实际使用；
- **故障安全文件**：失败写入不覆盖旧检查点，临时文件不得被重启扫描误认为有效文件。
- **构建与发布包**：冻结支持的编译器/MPI 组合、Release 编译选项、第三方许可证、安装或
  便携运行目录和最小示例，发布包必须从干净 checkout 可重复生成。
