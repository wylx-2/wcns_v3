# WCNS v1.1.0 详细开发计划

状态：**2026-09-11 阶段 R 自动卡口通过，候选为 `v1.1.0-r-candidate.1`。依项目负责人
连续执行 R→S→T 的授权，R→S 不设人工停点；R 直接合入后进入 S。S、T 仍各自严格执行设计、
实现和自动验收卡口，S→T 不设人工停点；T 完成后须在进入 U 前人工判断。**

基线版本：WCNS v1.0.0。计划版本：WCNS v1.1.0。数学与数值算法以仓库根目录
[`算法补充.md`](../算法补充.md) 第 11 节为权威规格；开发流程、Git 管理和公共卡口同时受
[`development-roadmap.md`](development-roadmap.md) 约束。本文件负责 v1.1.0 的版本目标、
阶段边界、任务拆分、量化验收、人工判断和发布闭环。

## 1. 版本定位与现状依据

v1.1.0 定位为“强稳健性、工程壁面量、可配置输运和性能基线”版本，不以扩大方程种类为目标。
当前串行发布构建的 48 项 CTest 和 MPI 发布构建的 84 项 CTest 已通过，可作为回归起点；
但已有人工算例给出下列必须优先处理的缺口：

1. Mach 5 圆柱使用 `WENO-Z + characteristic + Rusanov` 时在第 29 步出现负压候选，最终只能
   使用全域 `zero_order + Rusanov` 完成定性计算。现有面重构正性回退不能保证 SSPRK 子步
   更新后的真实单元仍位于物理可容许集合。
2. 圆柱 `Cp`、阻力、升力和黏性剪切仍由第一层单元中心后处理估算，生产程序没有通用真实
   边界面载荷、力矩和热流输出。
3. 底层已有常黏度和 Sutherland 模型，严格配置却只装配默认常黏度、`Pr=0.72`。
4. 当前残差热路径会反复建立临时通量/梯度容器和通信计划；计算与通信没有系统重叠，
   CGNS 输出和检查点仍由 root 汇聚后串行写入。现有算例只证明功能正确，没有冻结吞吐、
   内存和强扩展退化卡口。
5. 现有验证尚未独立冻结黏性空间阶、SSPRK3 时间阶、稳定 CFL 包络以及壁面载荷的网格收敛。
6. 完整测试只保存在开发仓库，尚未建立跨编译器的持续集成卡口；对外分发前的 WCNS 自有
   代码许可证也尚未由项目负责人决定。

## 2. v1.1.0 范围

### 2.1 必做范围

1. 建立 Linux GCC、Linux Clang、Linux OpenMPI 和 Windows 串行持续集成，并保留现有本地
   Intel MPI 发布矩阵。
2. 增加 SSPRK 子步后的真实单元物理容许性检查、共享面一致的局部无粘通量降阶、确定性
   重算和整步拒绝/缩步重试；任何降阶、重试及最终失败均可定位。
3. 建立边界面 quantity/statistic 注册路径，提供壁压、压力/黏性牵引、壁面热流、`Cp`、
   `Cf`、合力和力矩，并支持命名 patch、原生多块、运行时切分和 MPI。
4. 将常黏度、Sutherland、Prandtl 数及所需参数完整接入配置、摘要、manifest 和重启签名；
   未提供新键时保持 v1.0.0 的常黏度行为。
5. 建立黏性制造解空间收敛、SSPRK3 时间收敛、稳定 CFL 扫描、强激波稳健性、壁面载荷和
   串行/MPI 等价性验收。
6. 对热路径进行可复现剖析，持久化可复用工作区、通信计划与缓冲区；在不改变数学结果的
   前提下建立吞吐、内存、通信和 I/O 性能卡口。
7. 完成配置兼容、检查点策略、安装包、用户/开发文档、已知限制和正式发布说明。

### 2.2 明确非目标

以下能力不进入 v1.1.0；任何一项若要提前，必须先修订本计划和《算法补充》，重新进行当前
阶段的人工冻结：

- 低 Mach 预处理、隐式推进、本地时间步、多重网格和双时间步；
- RANS、LES、DNS 专用亚格子模型、转捩、多组分、化学反应和真实气体；
- 非结构、混合、重叠、运动网格和 AMR；
- 稳定二进制 ABI、运行时动态插件和脚本表达式源项；
- HDF5/并行 CGNS 后端；v1.1.0 只允许在 ADF/root 写入架构下做有界内存汇聚和性能改善；
- 通用任意曲面插值切片、滑移接口和非共形连接。

## 3. 版本级不可破坏契约

1. `phenglei_wcns` 与 `scmm6_wcns` 的几何、线性插值、通量差分和边界闭合继续成套隔离。
2. 同一共享连接面只有一个权威数值通量；降阶级别也必须先在相关 rank 间合并，再由 owner
   计算和发布，接收侧不得独立选择级别或重算。
3. 真实单元以外的坐标、度量、梯度及物理边界边/角 ghost 仍为非法域。新增壁面量只能使用
   `BoundaryGeometry`、真实边界迹和真实单元/面梯度。
4. 已接受 SSPRK 子步的状态必须有限并满足统一 `NumericalFloors`；不得用无日志截断密度、
   压力或温度伪造成功。
5. 被拒绝的子步或整步不得推进 step/time，不得触发正常输出事件，不得写成可重启检查点。
6. 降阶后的面通量仍进入原 profile 的通量差分；不能偷偷把整个空间算子切换为另一套有限
   体积路径。最终稳健级别是相邻单元零阶状态加 Rusanov 通量，而不是零通量或复制旧通量。
7. 新输运参数、稳健性开关和任何改变数值轨迹的参数必须进入配置摘要、manifest 和 restart
   signature；纯输出选择不得进入数值签名。
8. v1.0.0 合法配置在不增加新键时必须继续解析，并映射为 `constant, mu_ratio=1, Pr=0.72`。
9. v1.0.0 检查点只有在网格、旧数值签名及上述默认迁移语义均一致时才允许恢复；不能兼容时
   必须在推进前一致拒绝并报告具体字段。
10. 优化提交不得与算法变化混合。每项优化必须有数值等价性、性能对照和可回退的独立提交。

## 5. 每阶段统一执行步骤

每个阶段 P--U 均执行以下闭环，顺序不得调换。P、R、S 在步骤 7 以对应书面授权代替候选后的
再次人工等待，自动验收成功即可执行步骤 8 并进入下一阶段；T 仍在步骤 7 停止等待人工判断：

1. **检查基线**：记录集成分支提交、工作树、工具链、测试数和已登记的用户文件。
2. **编写阶段设计**：建立 `docs/v1.1.0/stage-<p-u>-design.md`，写清任务、接口、数学引用、
   合法域、并行/重启影响、测试映射、非目标和量化阈值。
3. **人工冻结设计**：项目负责人明确批准。涉及数学变化时，必须先同步修改《算法补充》并
   运行规格检查；设计未冻结不得修改生产 C++。
4. **小任务实现**：每个小任务只解决一个目标，执行最小测试、受影响回归和
   `git diff --check` 后独立提交并推送阶段分支。
5. **阶段前验**：完成串行/MPI Release 构建、单元/公式测试、数值验收、失败路径、性能或
   输出专项检查；前验失败只形成普通修复提交，不冒充正式验收。
6. **正式自动验收**：从已确认的干净构建执行完整命令，保存机器、提交、命令、耗时、阈值和
   原始结果；成功或失败都写入 `docs/v1.1.0/stage-<p-u>-acceptance.md` 并提交。
7. **候选与人工判断**：自动验收成功后创建不可移动的阶段候选标签并推送；项目负责人检查
   代码差异、报告和代表结果，明确“批准”或“要求修改”。
8. **合并或修订**：批准后以非快进方式合并到 `release/v1.1.0`，再开始下一阶段；要求修改时
   保留旧候选标签，在原阶段分支修订并创建递增候选。

所有阶段共同使用以下卡口：

| 卡口 | 内容 | 失败结果 |
|---|---|---|
| V0 范围 | 阶段设计、非目标、数学引用和量化指标已人工冻结；P/Q 使用 2026-09-11 连续推进授权 | 不开始生产实现 |
| V1 接口 | 数据所有权、合法域、维数、边界、多块/MPI 和重启语义唯一 | 返回设计修订 |
| V2 构建 | 串行/MPI Release、警告策略、`git diff --check` 通过 | 不做数值验收 |
| V3 单元/公式 | 新公式、索引、符号、异常和配置路径有自动测试 | 正式验收失败 |
| V4 回归 | 当前串行/MPI CTest 全通过，无未解释基线变化 | 正式验收失败 |
| V5 数值 | 当前阶段解析、制造、守恒、精度和稳健性阈值通过 | 不得静默放宽阈值 |
| V6 并行/重启 | 单块、多块、1/多 rank、共享面、失败一致性和重启通过 | 正式验收失败 |
| V7 证据 | 设计、验收报告、配置、日志、图表、提交和远程状态完整 | 不创建候选标签 |
| V8 人工 | 项目负责人明确批准当前候选 | 不合并、不进入下一阶段 |

## 6. 阶段 P：规格冻结、CI 与可重复基线

### 6.1 目标与任务

1. P0：人工审查本计划及《算法补充》第 11 节，冻结 v1.1.0 的必做/非目标、正性判据、载荷
   符号、输运键和性能指标定义。
2. P1：登记版本基线。记录 `v1.0.0`、计划采用的开发仓库基准提交、v1.0 后已认可的算例提交、
   当前未跟踪或未提交用户文件。P 的基线和 CI **必须包含 Case07 四块圆柱算例**；当前
   `cases/manual/case06_2d_naca0012/` 及其 NACA0012 网格明确不属于 P/Q 范围，保持未跟踪且
   不得顺带提交。使用 `release/v1.1.0` 和独立阶段分支管理版本。
3. P2：增加持续集成：Linux GCC Release 串行、Linux Clang Release 串行、Linux GCC/OpenMPI
   Release 2/4 rank、Windows MSVC 或 MinGW Release 串行；另设 Linux ASan/UBSan Debug。
4. P3：CI 只使用小型确定性网格，不提交运行生成物；失败保留必要日志和 CTest JUnit，成功
   不上传大量场文件。
5. P4：冻结数值基线：自由流、等熵涡、Sod、双马赫反射 smoke、Couette、导热、制造源、
   周期多块、检查点与异 rank 重启。
6. P5：冻结性能基线：至少包含 100x100 二维等熵涡、四块圆柱无输出短算和
   36x48x36 三维黏性短算。分别记录初始化、度量、无粘、粘性、halo、残差归约、输出、
   checkpoint 的墙钟时间和峰值常驻内存。
7. P6：把基线写为机器可读 JSON/CSV，记录 CPU、编译器、优化选项、MPI、rank 绑定和重复次数；
   性能测试不放入普通功能 CI 的硬实时阈值，而在固定基准机上执行。

### 6.2 自动验收卡口

- 原有串行 48 项、MPI 84 项测试全部通过；若测试数因 v1.0 后已认可提交变化，以 P1 冻结的
  清单为准并解释差异。
- 四类 CI 构建至少连续两次通过；ASan/UBSan 无未解释报告。

- `git status --short` 只允许出现 P1 明确登记且不属于本阶段的用户文件。

## 7. 阶段 Q：强激波物理容许性与事后稳健化

### 7.1 目标与任务

1. Q0：建立 `stage-q-design.md`，逐项引用《算法补充》11.1--11.3，冻结检测时刻、降阶梯子、
   离散支持域、跨 rank 级别合并、重算次数、缩步因子、最小时间步和诊断 schema。
2. Q1：实现真实单元容许集合检查。每个 SSPRK 候选子步在提交前检查有限性、密度、压力、
   温度和内部能；报告首个/最差位置，不修改候选值掩盖错误。
3. Q2：实现事后 troubled-cell 检测和 face downgrade plan。降阶级别按所选高阶配置、同方案
   primitive、`linear5`、`zero_order + Rusanov` 递增；只允许向更稳健级别单调升级。
4. Q3：根据当前 profile 通量差分的实际离散支持域，把 troubled cell 请求传播到所有影响该
   单元的面；连接面级别取相关请求最大值，并由权威 owner 重算、发布。
5. Q4：只重算受影响的无粘面通量和相应通量 halo，然后重组完整残差。黏性通量和源项保持
   同一候选状态/子步时间；不得重复乘时间步或 `1/Re`。
6. Q5：最低通量级别仍不能生成合法候选时，拒绝整个时间步、恢复步首状态、统一缩小 `dt`
   并重算三个 SSPRK 子步。所有 rank 通过一致归约决定接受、重试或失败。
7. Q6：增加配置和诊断：启用状态、最大局部重算轮数、最大整步重试数、缩步因子、最小 dt、
   各级面数、troubled cell 数、重试次数、最小 rho/p 及首个位置。影响轨迹的键进入重启签名。
8. Q7：增加常量/光滑波、Sod、极低压、强激波、双马赫反射和 Mach 5 圆柱测试；注入跨块、
   跨 rank 和物理边界附近失败，验证级别传播和无死锁失败。

### 7.2 自动验收卡口

- 关闭新稳健模式时与 P 阶段冻结基线逐位一致；Q0 默认值由 2026-09-11 连续推进授权下的阶段
  设计冻结，不能在实现中暗改。
- 每个被接受的 SSPRK 子步均满足 `rho >= rho_floor`、`p >= p_floor` 且全部状态有限。
- 常量流不触发降阶；光滑等熵涡的既有收敛阶不下降，误差增量不超过 Q0 冻结比例。
- 单块、多块以及 1/2/4 rank 对 troubled cell、共享面最终级别、各级计数和接受状态一致；
  最终守恒场满足冻结容差。
- 共享面只计算和记录一次权威通量。任意降阶后仍满足全局守恒权重恒等式；关闭源项的周期
  算例总质量、动量和能量漂移不高于 P 基线容差。
- Case07 Mach 5 至少在现有 48x32 网格推进到 `t=8`，不得全局选择 `zero_order`；允许的局部
  最低级别面比例和缩步次数由 Q0 基线人工冻结，报告必须给出时空分布。
- 超过最大重算/重试或低于最小 dt 时所有 rank 返回数值失败，不写正常终场或检查点。

### 7.3 人工判断

人工检查至少包括 Mach 5 密度/Mach 等值图、激波位置和厚度、降阶面时空图、最小 rho/p
历史、守恒历史、零阶基线及原高阶失败基线对照。项目负责人判断局部耗散是否可接受、是否
存在大面积持续最低阶、结果是否值得进入工程输出阶段。批准后合并 Q 并进入 R。

自动卡口结果、Case07 数值证据和 Git 状态见
[`v1.1.0/stage-q-acceptance.md`](v1.1.0/stage-q-acceptance.md)。

## 8. 阶段 R：边界面工程量、载荷与热流

### 8.1 目标与任务

1. R0：建立 `stage-r-design.md`，冻结《算法补充》11.4 的法向、牵引和热流符号，以及参考面积、
   参考长度、力矩中心、来流状态和二维单位展向长度的输入语义。
2. R1：建立 `IBoundaryQuantity`/registry 或等价单一职责接口。quantity 只遍历命名物理 patch
   的真实边界面，声明依赖、单位、缩放、标量/矢量分量和可用边界类型。
3. R2：实现边界面 `p_w`、`T_w`、`mu_w`、压力牵引、黏性牵引、总牵引、壁面热流、`Cp` 和
   切向 `Cf`。数据必须复用求解器的 `ViscousBoundaryTrace` 和真实面梯度语义，不另造一套
   第一层单元近似。
4. R3：实现按 patch 的力、力矩、压力/黏性分量以及用户给定方向上的升力/阻力系数。运行时
   切分后按原 CGNS patch 名重组；MPI 使用确定性归约并在所有 rank 上得到一致统计值。
5. R4：增加边界面 Tecplot/CGNS 或稳定的表格输出。记录面中心、面积、法向、patch、原 zone、
   step/time、量名、无量纲/有量纲单位；原子提交和覆盖策略与现有输出一致。
6. R5：增加按步/时间调度的载荷历史；重启后不重复物理时刻。输出配置不改变数值 restart
   signature，但完整输入仍进入 config digest 和 manifest。
7. R6：验证静止均匀流、Couette、线性导热、对称圆柱、压力已知封闭曲面、移动壁和等温/
   绝热壁；覆盖二维、三维、原生多块、运行时切分和 MPI。

### 8.2 自动验收卡口

- 均匀压力作用于闭合曲面的净压力力达到离散几何闭合容差；对称圆柱升力接近零且上下半壁
  贡献符号相反。
- Couette 壁面切应力和线性导热壁面热流达到解析值，并随网格加密达到 R0 冻结阶数。
- 绝热壁法向热流为零；等温壁热流上下壁符号与能量平衡一致。
- 同一算例的面面积、法向、逐面量、总力和力矩在单块/多块、1/2/4 rank 下满足冻结容差；
  旋转周期不得重复计入物理边界。
- 有量纲与无量纲输出按参考尺度往返一致；二维明确记录“单位展向长度”。
- Case07 不再依赖第一层单元估算即可产生 `Cp`、压力阻力、黏性阻力和升力历史。

### 8.3 人工判断

人工审查圆柱表面 `Cp/Cf`、压力/黏性阻力拆分、升力历史和网格敏感性；核对法向和热流符号，
并抽查 Tecplot/CGNS 独立重读。若任何力的正方向只能靠后处理脚本猜测，R 不得批准。

阶段 R 自动验收结果见
[`v1.1.0/stage-r-acceptance.md`](v1.1.0/stage-r-acceptance.md)。根据连续推进授权，本轮不在
R→S 之间设置人工停点；上述人工检查项保留到 T→U 集中卡口，不被记作已经人工批准。

## 9. 阶段 S：输运配置与数值收敛验证

### 9.1 目标与任务

1. S0：建立 `stage-s-design.md`，冻结《算法补充》11.5 的配置键、单位、默认迁移和合法域。
2. S1：把 `constant` 与 `sutherland` 接入 `CaseConfig`、严格 parser、summary、模板、manifest
   和 restart signature。v1.0 配置缺省时映射到 `constant, mu_ratio=1, Pr=0.72`。
3. S2：启动时打印 `mu(T_ref)/mu_ref`、Pr、Sutherland 温度比以及代表性最小/最大温度下的
   黏度范围；非法、非有限、重复或与模型无关的键立即失败。
4. S3：建立常黏度与 Sutherland 的解析点值、尺度不变性、导热系数及粘性 CFL 测试；保证
   `1/Re` 仍只在粘性散度和时间步限制中出现一次。
5. S4：完成二维/三维黏性制造解的至少三层网格空间收敛，两套 profile 分别报告内部、边界和
   全局误差；不得只报告一个末态误差。
6. S5：以空间误差可忽略的周期问题执行至少四档 dt 的 SSPRK3 时间收敛；再对无粘、黏性、
   强激波和曲线网格分别扫描 CFL，区分“经验稳定范围”和“普适保证”。
7. S6：增加 v1.0 配置/检查点兼容测试、改变输运参数的重启拒绝测试，以及相同物理参数不同
   合法单位表示的等价性测试。

### 9.2 自动验收卡口

- 缺省新键的 v1.0 配置与 P 基线逐位一致；`T=1` 且参考黏度比为 1 时 Sutherland 恢复 1。
- Pr、黏度比、Sutherland 常数或任一运行温度非法时，在推进或写正常输出前一致失败。
- Couette、导热和制造解达到 S0 冻结的误差/阶数；SSPRK3 观测时间阶在渐近区达到 3 阶容差。
- CFL 报告包含成功、数值失败、触发局部降阶和触发缩步的边界，不把一次成功冒充稳定定理。
- 单块/多块、串行/MPI、连续/重启对输运状态和最终场满足冻结容差。

### 9.3 人工判断

项目负责人检查空间/时间 log-log 数据、是否进入渐近区、壁面闭合是否主导全局阶数、CFL
推荐值是否保守，以及 v1.0 检查点兼容策略是否可接受。只有完整原始数据和生成脚本可复现时
才能批准。

## 10. 阶段 T：热路径性能与并行扩展

### 10.1 指标

性能定义见《算法补充》11.6。P 阶段在固定机器上冻结基线后，默认目标为：

- 每个 RK 子步热路径动态分配次数减少至少 90%；
- 代表性纯计算算例的串行 cell-stage/s 中位数提升至少 1.5 倍；
- 足够大、每 rank 真实单元数不低于 T0 冻结下限的算例，4-rank 强扩展效率至少 70%；
- 数值等价性、错误诊断、重启和输出结果不得为了性能静默放宽；
- 性能目标只能在 T0 设计人工冻结前依据 P 基线调整，并必须记录原因，不能在验收失败后改线。

### 10.2 目标与任务

1. T0：建立 `stage-t-design.md`，用采样剖析和分段计时确认热点，列出每项优化的预期收益、
   数值风险、内存代价和独立回退方案。
2. T1：把每步不变的拓扑查询、面 owner、halo plan、消息长度/tag、profile 离散支持和 registry
   装配移到初始化阶段，状态版本只更新消息头，不重建几何映射。
3. T2：为 SSPRK 初始状态、无粘面通量、梯度操作数、真实梯度、粘性通量和 MPI pack/unpack
   缓冲建立持久工作区；按网格签名分配一次并重复清零/覆盖。
4. T3：在依赖允许处把 halo exchange 拆成 begin/finish：先发布接收和发送，再计算不依赖远端
   halo 的块内部区域，最后等待并计算连接邻域。无可证明重叠时保留同步路径。
5. T4：合并同一阶段可安全合并的全局归约，记录归约次数和字节数；停止、错误和诊断语义
   不能因减少集合通信而改变。
6. T5：在 root/ADF 架构内按 zone/字段分块汇聚和写出，避免同时常驻全部全局字段副本；
   不在本阶段伪装成并行 CGNS I/O。
7. T6：增加结构化计时与可选性能 manifest。默认低开销；详细计时模式必须在日志中显式标记。
8. T7：在固定机器运行串行、2/4/8 rank 强扩展、等负载弱扩展、输出和 checkpoint 基准；
   保存中位数、离散度、峰值内存和剖析摘要。

### 10.3 自动验收卡口

- 每个优化提交分别通过 P--S 全量回归和数值签名对照；浮点归约顺序变化必须预先写入 T0
  并使用量化容差，不能以“并行本来不一致”为解释。
- 关闭详细计时时，代表算例额外开销不超过 2%；持久工作区不得跨网格或重启错误复用版本。
- 达到 10.1 的分配、串行吞吐和 4-rank 效率目标；未达到时正式验收失败，除非先回到 T0
  修订设计并重新人工冻结。
- 1/2/4/8 rank 不死锁，错误注入仍一致失败；通信重叠路径由消息版本和 NaN/哨兵测试证明
  没有提前读取未完成 halo。
- 分块输出独立重读与内存值一致，峰值 root 内存符合 T0 冻结上界。

### 10.4 人工判断

人工检查火焰图或等价剖析、优化前后分段时间、内存、强/弱扩展曲线和代码复杂度。若性能
收益依赖关闭检查、改变算法或降低输出精度，不予批准。项目负责人可拒绝收益过小而维护成本
过高的重叠实现，并保留已验证的工作区优化。

## 12. Git 与仓库管理细则

### 12.1 分支和标签

```text
main
  \-- release/v1.1.0
        \-- stage/v1.1.0-p
        \-- stage/v1.1.0-q
        \-- stage/v1.1.0-r
        \-- stage/v1.1.0-s
        \-- stage/v1.1.0-t
        \-- stage/v1.1.0-u
```

- `main` 只接受最终人工批准的正式版本合并和必要热修复。
- `release/v1.1.0` 是版本集成分支，只接受已人工批准阶段的 `--no-ff` 合并。
- 每个阶段分支从当时的 `release/v1.1.0` 创建；不得提前把下一阶段代码混入当前阶段。
- 自动验收成功使用 `v1.1.0-<stage>-candidate.N`；人工批准可增加
  `v1.1.0-<stage>-approved.N`；最终候选使用 `v1.1.0-rc.N`。
- 标签一经推送不得移动或复用。禁止强制推送、rebase 已同步阶段历史和删除失败候选来掩盖问题。

### 12.2 提交粒度

建议提交前缀为 `docs:`、`test:`、`feat:`、`fix:`、`perf:`、`build:`、`release:`。一次提交只
包含一个可独立解释和验证的主题。例如 Q 阶段至少拆成容许集合、级别计划、共享面同步、
SSPRK 重试、诊断、测试六类提交，不以一个巨型 `feat: v1.1` 覆盖全部历史。

每次提交前至少执行：

```powershell
git status --short --branch
git diff --check
cmake --build <affected-build> --parallel
ctest --test-dir <affected-build> -R <minimum-affected-set> --output-on-failure
```

正式验收前再执行完整串行/MPI Release 矩阵。生成的场、checkpoint、临时构建目录、剖析原始
缓存和用户未批准的大网格不得进入普通源码提交；需要保存的基准摘要、脚本、小型网格和图表
必须在阶段设计中列入交付物并控制体积。

### 12.3 脏工作树和用户文件

阶段开始时把已有未提交文件按“本阶段输入、用户保留工作、应忽略生成物”登记。用户保留工作
不得被移动、删除、格式化、暂存或提交；推荐用独立 worktree 隔离开发。发现与当前阶段目标
重叠的用户修改时停止该文件的写入并请项目负责人判断，不能用 `reset --hard`、覆盖式 checkout
或清理整个目录解决。

### 12.4 正式验收失败

正式验收一旦开始，无论成功或失败都要提交验收报告。失败时：

1. 不创建候选标签、不合并版本分支、不开始下一阶段；
2. 报告首个失败、完整失败清单、环境、提交和原始命令；
3. 修复按独立提交进入同一阶段分支；
4. 重跑受影响专项和完整阶段矩阵；
5. 新的成功候选使用递增编号，不改写旧报告和历史。

## 13. 配置、重启和文档迁移策略

1. v1.1.0 继续接受 `schema_version=1`，新增键均为可选且有与 v1.0 一致的安全默认；本版本不
   仅为增加键而创建 schema 2。
2. 稳健性配置建议使用 `robustness.*` 独立命名空间，输运配置使用 `transport.*`，边界载荷
   输出使用 `output.boundary.*`/`output.loads.*`。最终键名在相应阶段设计人工冻结。
3. parser 继续拒绝未知键、重复键、非有限数和模型无关参数；配置摘要显示最终生效值，不只
   显示用户输入片段。
4. restart signature 增加显式版本段。读取 v1.0 检查点时先应用兼容映射，再比较数值语义；
   不通过时列出第一个不兼容字段，不提供 `force_restart` 绕过。
5. 每个新键同步更新完整模板、用户手册、运行速查、开发指南、合法/非法配置测试和 manifest
   示例；代码、模板和文档不得跨阶段长期不一致。

## 14. v1.1.0 完成定义

只有同时满足以下条件才能称为完成：

1. P--U 每个阶段都有设计、自动验收报告、候选标签和明确人工批准记录；
